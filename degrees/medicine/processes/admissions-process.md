# Proceso de admisión (Medicina en España)

## Objetivo

Definir los pasos que debe seguir un estudiante para:

- identificar universidades adecuadas
- solicitar información
- iniciar el proceso de admisión
- completar su candidatura

El sistema debe facilitar este proceso reduciendo fricción y guiando al usuario en cada paso.

---

## Fases del proceso

### 1. Exploración inicial

El estudiante:
- busca información sobre estudiar Medicina en España
- no tiene claridad sobre sus opciones
- necesita orientación general

Rol del sistema:
- ofrecer diagnóstico inicial
- explicar estrategia general
- incentivar registro para recomendación personalizada

---

### 2. Recomendación personalizada

El estudiante:
- obtiene una lista de universidades recomendadas
- entiende su estrategia (ambiciosa / intermedia / segura)

Rol del sistema:
- presentar opciones claras
- explicar por qué cada universidad encaja
- preparar al usuario para tomar acción

---

### 3. Solicitud de información

El estudiante:
- quiere contactar con universidades
- quiere recibir más información

Rol del sistema:

- permitir solicitar información a múltiples universidades con un solo clic
- centralizar el proceso
- registrar qué universidades interesan al estudiante

Valor clave:
- captura de lead
- inicio del tracking del usuario

---

### 4. Inicio del proceso de admisión

El estudiante:
- decide aplicar a una o varias universidades

Rol del sistema:

- facilitar inicio de solicitud de admisión
- guiar en documentación necesaria
- simplificar el proceso

Valor clave:
- dato crítico para el sistema
- permite medir intención real

---

### 5. Preparación de pruebas de acceso

El estudiante:
- necesita superar pruebas de admisión (en algunos casos)

Rol del sistema:

- detectar esta necesidad
- recomendar preparación académica
- ofrecer productos de preparación

Momento clave de monetización

---

### 6. Seguimiento del proceso

El estudiante:
- está en proceso de admisión
- necesita saber estado de sus solicitudes

Rol del sistema:

- mostrar estado de cada universidad
- recomendar siguientes pasos
- mantener engagement

---

### 7. Resultado de admisión

El estudiante:
- recibe respuestas de universidades

Rol del sistema:

- registrar resultado:
  - admitido
  - lista de espera
  - rechazado

Valor clave:
- generación de datos históricos
- mejora del sistema de recomendación

---

## Principio clave

El sistema no debe limitarse a informar.

Debe:

- guiar
- simplificar
- acelerar decisiones
- reducir fricción

---

## Integración con el funnel

- Nivel 1 → orientación (sin acción)
- Nivel 2 → recomendación + preparación para acción
- Nivel 3 → ejecución (información, admisión, seguimiento)

---

## Datos clave a capturar

En cada fase, el sistema debe registrar:

- universidades consultadas
- universidades seleccionadas
- solicitudes iniciadas
- solicitudes completadas
- resultados de admisión

Estos datos permiten:

- mejorar el sistema de recomendación
- estimar probabilidades reales
- crear ventaja competitiva

---

## Regla crítica

El sistema debe facilitar que el estudiante realice acciones dentro de la plataforma, no fuera.

El objetivo es:

- centralizar el proceso
- reducir fricción
- capturar datos estratégicos

---

## Resultado esperado

El estudiante debe:

- entender qué hacer en cada momento
- poder avanzar fácilmente en el proceso
- sentir que el sistema le guía

El sistema debe:

- aumentar la tasa de acción
- capturar datos
- mejorar con cada usuario
