# Flujo de usuario y lógica de plataforma

## Objetivo

Definir cómo interactúa el usuario con la plataforma y cómo el sistema:

- captura leads
- genera engagement
- facilita el proceso de admisión
- maximiza la conversión

---

## Tipos de usuario

El usuario puede ser:

- estudiante
- padre o madre
- tutor

El sistema debe:

- identificar el tipo de usuario
- adaptar el lenguaje y recomendaciones
- facilitar la conexión entre usuarios relacionados

---

## Relación padre / estudiante

El sistema debe permitir:

- compartir recomendaciones entre usuarios
- invitar a otro usuario (padre ↔ hijo)
- vincular cuentas relacionadas

Valor:

- captura de múltiples leads
- mejora de datos
- mejor comprensión del proceso de decisión

---

## Incentivos de registro

El sistema debe ofrecer razones claras para registrarse:

- acceso a recomendación completa personalizada
- alertas de fechas clave de admisión
- acceso a guías detalladas por universidad
- seguimiento del proceso en un único lugar

El registro debe percibirse como una herramienta útil, no como una barrera.

---

## Alertas y seguimiento temporal

El sistema debe:

- detectar el momento del proceso del usuario
- enviar alertas relevantes:

  - apertura de convocatorias
  - fechas límite
  - pruebas de admisión

Objetivo:

- evitar pérdida de oportunidades
- aumentar engagement
- reforzar valor de la plataforma

---

## Acceso a contenido avanzado

Usuarios registrados deben tener acceso a:

- guías completas de universidades
- comparativas
- contenido explicativo del proceso
- recomendaciones ampliadas

Esto actúa como:

- incentivo de registro
- herramienta de decisión
- posicionamiento de autoridad

---

## Estado del usuario

El sistema debe identificar el estado del usuario:

- exploración inicial
- evaluando opciones
- listo para aplicar
- en proceso de admisión
- esperando resultados

Las respuestas deben adaptarse a este estado.

---

## Principio clave

El sistema no solo informa.

Debe:

- guiar decisiones
- reducir fricción
- aumentar probabilidad de admisión
- capturar datos en cada paso

---

## Relación con otros componentes

- criteria → define qué recomendar
- funnel → define cómo responder
- processes → define qué ocurre en el mundo real
- product (este documento) → define cómo se usa la plataforma
